# Saved examples for testing changes

Before an approved change goes live, the weekly review replays it against these examples and checks the result
still gets them right. Each file is one real case with client details removed: what came in, what a good
result looks like (Chris's approved words where we have them), and what must never happen.

Add a case whenever: Chris approves a draft as-is (a good example), Chris rewrites one (the rewrite is the
expected result), or something went wrong (the case must now come out right). Keep 3–10 per job. No client
names, emails, phone numbers or deal numbers: use [seller], [agent], [amount].
